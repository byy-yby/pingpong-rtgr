# IMU 姿态接入（维特智能 WT9011DCL-BT5.0）

把插在乒乓球拍柄末端的维特智能 IMU（WT9011DCL-BT5.0，**蓝牙 5.0 / BLE**）读进来，在
`live_control` 的 3D 窗口里实时显示**握拍手（右手腕）的球拍朝向与位置**：球拍朝向来自
IMU，位置绑定到姿态重建检测到的右手腕（假设 IMU 位置 ≈ 手腕位置）。

## 用法
1. `scripts/live_control.py` 里按 **p** 开姿态重建（提供右手腕 3D 位置），再按 **i** 开 IMU。
2. 按 i 后把**球拍平放在桌面原点**（拍面朝上、手柄大致朝 +X），保持约 1 秒不动——
   该姿态被锁成参考（`R_home`），之后球拍朝向都相对它输出（消除 IMU 安装角偏差）。
3. 3D 窗口里球拍 + 坐标架随 IMU 朝向实时旋转，且**锚定在检测到的右手腕上**随手臂移动。
   多人时自动选**右手腕离桌面原点最近的人**（用户初始化时站在原点那一侧）。
4. 再按 **i** 关闭，球拍层隐藏；重开 i 会重新锁定参考姿态（可用来重置零位）。
- 扫不到 / 有多个模块时用 `--imu-mac AA:BB:CC:DD:EE:FF` 或 `--imu-name <名字子串>` 直接指定。
- 上报率默认提到 **100Hz**（`--imu-rate` 可改，支持 0.2~200Hz）——模块默认只有 10Hz，
  60fps 窗口里球拍会明显顿挫。
- 没开姿态重建时球拍显示在固定锚点（桌面中心上方 0.35m），只转不跟手。

## 参考姿态初始化（R_home 锁定）
- 按 i 首次连接后，头 `_IMU_INIT_N`（20）个有效朝向样本被采集；窗内样本互相偏差
  `≤5°`（用户静止）时锁成 `R_home = so3_project(均值)`——静止约 0.2s 即锁定。
- 之后每个朝向都输出相对旋转 `R_rel = R_home^T @ R_imu`——初始化那一刻球拍正好平放
  朝上（R_rel=I），拿起转动时 R_rel 即拍面的真实朝向。
- 用户还在动时滚动窗继续采（丢最早一半样本，限频提示「请保持静止」），**不设硬超时**，
  避免锁到运动中的模糊均值；实在锁不上就重按 i 重新初始化。

## 右手腕锚点（viewer3d.right_wrist_anchor）
- halpe26 / coco17 骨架按名字查 `right_wrist`（halpe26 = 索引 10）的 3D 世界坐标。
- 多人时选**离桌面原点 (0,0,0) 最近的有效右手腕**（`_WRIST_MIN_CONF=0.3` 置信度门限），
  即按 i 时把球拍放在原点的那一侧球员。
- 主循环姿态重建每帧 `viewer3d.set_imu_anchor()` 写锚点；IMU notify 线程 `set_imu_orientation()`
  写朝向——两者都是线程安全写入，渲染线程合并，绕开主循环 ~20FPS 帧率钳制。

## BLE 连接
- GATT 服务 `0000ffe5`、notify 收数据 `0000ffe4`、写命令 `0000ffe9`
  （UUID 来自维特官方 SDK `WitBluetooth_BWT901BLE5_0` 的 `BleUUID.java`）。
- 依赖 `bleak`（`pip install bleak`，已装进 `tt` 环境）。
- 广播名以 **"WT"** 开头（如 WT9011DCL…）。
- 连接后自动经 `ffe9` 下发官方写命令提上报率：解锁 `FF AA 69 88 B5` → 设 RATE
  `FF AA 03 <val> 00` → 保存 `FF AA 00 00 00`（**NORMAL 协议 5 字节、无校验**，
  见官方 SDK `WitWriteReg()` / Android 例程 `setReturnRate()`）。失败不影响连接。

## 数据协议（⚠️ BLE 与 UART 帧格式不一样）
- 默认上报 **0x61 组合包**（加速度6B + 角速度6B + 角度6B）@10Hz（可 0.2~200Hz）。
- 角度 = int16 / 32768 × 180°（欧拉 Z-Y-X）；四元数 = int16 / 32768。数据一律小端。
- 兼容经典 0x53 角度 / 0x59 四元数。
- **UART 帧**：`0x55 | Flag | Data | Checksum`（共 `2+len+1` 字节），校验和 = 从 0x55 起到数据末之和的低 8 位。
- **BLE 帧（实测坑，`imu_probe.py` 抓的原始数据）**：0x61 组合包只有
  `0x55 | 0x61 | 18B 数据` 共 **20 字节，没有校验字节**；模块把连续多个包塞进同一条
  notify（80B=4 包、40B=2 包）。解析器必须用 `WitMotionParser(checksum=False)`（20B
  无校验）——若按 21B 带校验解析，每个包都凑不齐/校验失败，有效包只剩 1/256 的运气值，
  **实测表现就是「能连上但姿态几乎不动 / 偶发跳一下」**（本模块唯一的帧格式坑）。

## 模块
- `witmotion.py`：0x55 协议解析 + 角度/四元数 -> 旋转矩阵（纯 numpy，无 I/O）。
- `reader.py`：`ImuReader` 后台 BLE 线程（bleak，扫描/连接/notify）。

## 可靠性与排查（卡顿 / 偶尔停更）
- **卡顿**：默认 10Hz 上报在 60fps 窗口里就是顿挫的 → 已自动提到 100Hz。
  若还是卡，看 `[IMU] 数据 x.x 包/秒（期望 100Hz）`——明显偏低说明链路/距离有问题，
  可 `--imu-rate 50` 降档保稳。
- **偶尔停更**：连接断开或假死会自动重连（指数退避，日志会打 `已断开` / `强制重连`）。
  一直连不上 = 模块没上电 / 被手机占用 / 距离太远；断开又自动重连成功也同理。
- **看门狗**：已连接但 >4s 无有效报文会强制重连（`is_connected` 在链路假死时不更新）。
- **朝向推送绕过主循环**：notify 线程经 `on_orientation` 回调直接把旋转矩阵写进 3D
  场景，不受 `live_control` 主循环 ~20FPS 钳制。

## 坑
- 模块上电后可能被手机 / 上位机占用（BLE 一般只允许单连接），连不上时先断开其它设备，或用 `--imu-mac` 直接指定。
- 需有可用的蓝牙适配器（`bluetoothctl list` 应看到 hci0）。
- **未完成**：IMU 安装角（IMU 轴 vs 拍面朝向的固定偏移）默认按「拍面法线=+Z、手柄=+X」，
  实际安装角需按实物校准后在 `viewer3d._paddle_mesh` / 朝向换算处补一个固定旋转。
