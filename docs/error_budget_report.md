数据：`20260908_161014`(2015 帧) / `20260908_161102`(2728 帧) / `20260908_161147`(719 帧)，
均 `--assoc tracker` + 下半身门默认开。脚本见 `scripts/error_budget/`（全部可复跑）。

口径：与 `recon_meta.json` 的 `reproj_err_mean_px_median` 一致——逐帧每人取**拟合视角**
（已剔裁边）里 conf>0 的关节，SMPL 投影 vs 2D 观测的像素距离，先对 (视角×关节) 取均值
→ 对人取均值 → 对帧取中位数。复现值与 meta 差 ≤0.8px（12.96 vs 12.94 / 13.81 vs 14.60 /
13.03 vs 13.27）。

## 3. 误差来源占比（核心结论）

**方法**（`errbudget.py` + `shares.py`）：逐观测分解
`r_fit² = r_pred²(2D白噪声经三角化放大) + r_sys²(地板超出) + r_mod²(SMPL 超出地板)`，
其中 `r_in` 是同一批 2D 点做加权 DLT 三角化后回投各视角的残差（**地板**：任何 3D 模型
都解释不了的那部分观测不一致）；`r_sys²` 再用**刚性 ArUco 标记**在同样 DLT 下测出的
跨视角地板 `c(nv)` 拆成「标定」与「2D 关键点系统性偏差」。
占比 = 逐样本方差占比的中位数。

**上身（三个 session 一致）**：

| 来源 | 161014 | 161102 | 161147 |
|---|---|---|---|
| 2D 白噪声（经三角化） | 0.5% | 0.5% | 0.5% |
| **2D 关键点系统性偏差** | **43.1%** | **39.1%** | **39.5%** |
| 相机标定（外参为主） | 9.1% | 4.4% | 5.5% |
| SMPL 拟合/模型 | 17.3% | 29.9% | 29.4% |

**下身**：2D 关键点 45.6-48.0%、标定 0.8%、SMPL 46.2-49.1%。
**髋**：2D 关键点 25.5-33.8%、标定 4.5-8.7%、SMPL 41.3-53.6%。

回答用户的四问：

1. **相机内参误差**：没有独立证据指向它。四台内参标定 RMS 0.35-0.51px 相近；
   ArUco 残差**不随像面半径变化**（c1 在 0-200/200-400/400-600px 分别为 10.3/9.5/7.7px，
   c3 为 9.6/9.5/8.8/10.6px）→ 若是焦距/畸变问题，残差应随半径增长。**<2%**。
2. **相机外参误差**：**4.4-9.1%**（上身）。见 §4，是唯一被独立真值证实、且已被修正验证的一项。
3. **2D 关键点识别误差**：**39-48%，最大项**。其中随机抖动（时间二阶差分 σ=0.9-1.5px）
   只占 0.5%；主体是**每视角系统性偏差**——两视角对同一关节的分歧 5-7.6px 远大于 σ，
   且随置信度剧烈变化（conf 0.9 → 2.2cm，conf 0.3-0.5 → 14.9cm）。
4. **三角重建误差（几何放大）**：**0.2-0.5%**。σ=1.1px 经 2-3 视角三角化后只放大到
   0.6px（`r_pred = σ·sqrt((2N−3)/(2N))`）。三角化本身不是瓶颈；它的 3D 抖动
   （上身 2.1cm / 下身 7.3cm）来自输入的 2D 误差。
5. **SMPL 拟合/模型误差**：**17-30%（上身）/ 46-49%（下身）**。下身是重灾区。

## 4. 独立真值：桌面四角 ArUco 标记（`aruco_gt.py`）

录像里始终能看到桌面四角的大 ArUco（ID0-3），它是**静止、亚像素、已知尺寸**的刚体，
可以直接量标定误差，不需要姿态模型。

- **尺度没问题**：标记中心间距 ID0→ID1 比 0.992-0.995、ID0→ID3 0.996-1.004、
  ID0→ID2 0.993-0.999 → **尺度误差 <1%**（注：标记黑方块实测 0.1751m 而非配置的 0.18m，
  是打印缩放；以实测值为基准算间距真值）。之前 TODO 里记的「~5.8% 尺度误差」不成立。
- **刚性目标跨视角残差（同样 DLT）**：2 视角 0.8-1.1px、**3 视角 4.5px**、4 视角 3.8-3.9px。
  对比姿态：2 视角 7.3-7.7px、3 视角 5.9-6.4px、4 视角 6.0-6.4px →
  **2 视角时标定只贡献 ~0.8px，姿态那 7px 几乎全是 2D 关键点误差**。
- **逐相机留一视角（LOO，≥3 视角）**，三个 session 完全一致：

  | 相机 | 161014 | 161102 | 161147 |
  |---|---|---|---|
  | c0 | 3.55 | 4.04 | 4.23 |
  | c1 | **8.52** | **8.94** | **8.95** |
  | c2 | 2.54 | 2.77 | 2.75 |
  | c3 | **9.75** | **9.54** | **9.52** |

  → **c1、c3 与其余相机在静止刚体上差 ~9px**；残差与像面半径无关 → 外参（位姿）问题，
  不是畸变/焦距。
- **交替 BA 重估外参**（`aruco_ba.py`：三角化 ↔ 逐相机 PnP，内参固定）：

  | 相机 | 位姿修正 | |Δt| | 修正前残差 | 修正后 |
  |---|---|---|---|---|
  | c0 | 0.20° | 1.59cm | 2.12px | 0.32px |
  | c1 | 0.41° | 2.07cm | 4.98px | 0.31px |
  | c2 | 0.43° | 1.12cm | 1.67px | 0.40px |
  | c3 | 0.21° | 1.56cm | 4.93px | 0.27px |

  即：**外参误差只有 0.2-0.4° 量级，却足以在 3-4m 距离上产生 5px 的重投影误差**。
- **修正是否真的有用**（`floor_fixed.py`，把修正外参代回去重算**姿态**地板）：
  5.53px → **4.87px**（−12%；4 视角关节 6.44 → 5.21px，−19%）。
  → 外参修正确实能降低姿态误差，但它只占地板方差的 ~22%，**不是主要矛盾**。

## 6. P0-1 落地：低置信度关节治理（固定观测集 A/B，2026-09-10）

**为什么必须「固定观测集」**：`--fit-conf` 只改拟合的输入，改不了指标的分母——提高阈值后
低置信度关节直接从重投影误差的分母里消失，于是「中位数变小」可以纯粹是**假提升**。
所有对比都用 `ab_eval.py` 在**同一批 (帧,人,视角,关节)** 上算：`--fit-conf 0.5` 与
`--fit-conf 0` 两组指标（后者把低置信度关节也计回来），另加一个**完全不看 2D 置信度**的
指标——根关节（body25 #19 骨盆）相邻帧位移（cm），它只吃 3D 输出。

8 个配置 × 3 段视频（161014 / 161102 / 161147，共 5462 帧）：

| 配置 | fit conf>.5 | outfit conf>.5 | fit conf>0 | outfit conf>0 | p0 中位 | p0 max | p1 中位 | p1 max |
|---|---|---|---|---|---|---|---|---|
| base (fit-conf 0.15) | 11.91 | 14.71 | 14.92 | 36.65 | 0.20 | 6.04 | 0.30 | **14.79** |
| c30 | 11.89 | 14.74 | 14.91 | 36.77 | 0.20 | 6.17 | 0.30 | 14.96 |
| **c50** | **11.83** | 14.63 | **14.89** | 36.74 | **0.19** | 6.06 | **0.27** | **7.68** |
| cons10 | 12.10 | **13.69** | 15.67 | 35.99 | 0.24 | 5.57 | 0.30 | 14.07 |
| c30cons10 | 12.07 | 13.70 | 15.66 | 35.93 | 0.24 | 5.56 | 0.29 | 7.55 |
| c30cons6 | 12.10 | **13.63** | 15.81 | 35.85 | 0.24 | 5.53 | 0.30 | 5.17 |
| c50cons10 | 12.18 | 13.77 | 15.80 | 35.99 | 0.24 | 5.50 | 0.28 | 3.96 |
| c50cons6 | 12.21 | 13.66 | 16.04 | 35.92 | 0.24 | 5.52 | 0.29 | 3.73 |

（单位 px，除根关节列 cm；fit = 拟合视角、outfit = 有观测但不在拟合组的留出视角）

**采纳 `--fit-conf 0.5`**（默认已改）：三段视频上 fit/outfit/conf>0 四个口径**全部不劣**，
根关节 p1 最坏跳变 14.79 → **7.68cm（−48%）**，中位 0.30 → 0.27cm。ViTPose 的 conf 中位
0.87~0.90，0.5 不会误杀真实关节。

**「多视角 3D 共识降权」实现了但默认关**（`obs_filter.py`，Cauchy
`w=1/(1+(r/σ)²)`，r = 2D 观测与阶段 D 鲁棒 3D 的重投影距离，超过 `--consensus-max` 直接丢）：
它让**留出视角**重投影 −7%（14.71→13.69px）——但留出视角恰好是共识参考用到的相机，
有循环成分；代价是拟合视角 +2%（11.83→12.18）与 p0 抖动中位 +0.04cm。**净账不划算**，
留 `--consensus-sigma 10` 给「要把最坏跳变从 7.7cm 再压到 4.0cm」的场合（p1 max 确实
降到 3.7~4.0cm）。

- **l 与 h 都比 b 好 ~0.75-1.1px（8-11%）**，收益集中在**下身/脚**（−1.4~−2.0px），
  正是遮挡外推最严重的部位。
- **h vs l 头对头**：161147 打平（−0.03px），161014 h 好 0.79px（下身 −1.66、脚 −1.40）。
- 根关节抖动（2 段合并，cm）：b → c50 → l → h = p1 max **14.79 → 7.68 → 3.69 → 3.86**，

  （l/h 把 p1 最坏跳变压到 ~1/4）。

**默认改为 `--pose-model vitpose-h-coco_25`**（离线不追速度就取最强，用户拍板）；
`vitpose-l-coco_25` 精度基本持平、快 ~2.8×，是速度敏感场合的替代。
模型放 `/mnt/newdisk1/vitpose/`，项目内软链 `data/weights/vitpose`。
⚠️ h 的 onnx 是「226KB 图 + 394 个外挂分片」同目录结构（~2.55GB），**分片必须与图同目录**。

## 复跑

```bash
T=scripts/error_budget
python $T/errbudget.py <session_dir> out.npz        # 逐帧/逐人/逐相机/预算/Sampson/时间
python $T/shares.py out.npz                         # 来源占比（可加口径）
python $T/aruco_gt.py <session_dir> 10              # 刚性真值：尺度/LOO/半径依赖/共面性
python $T/aruco_ba.py <session_dir> 10 5 fix.npz    # 交替 BA 重估外参
python $T/floor_fixed.py <session_dir> fix.npz      # 修正外参后的姿态地板
python $T/trend.py out.npz                          # 误差随时间/置信度/深度的变化
python $T/ab_eval.py <recon_dir> --poses <pose2d.json> --meta <recon_meta.json> \
       --label <tag> --json <out.json>              # 固定观测集 A/B（fit/outfit × conf 口径）
python $T/ab_pose_model.py --a <dirA> --poses-a <A 的 pose2d.json> --b <dirB>  # 跨 2D 模型公平比较
```
